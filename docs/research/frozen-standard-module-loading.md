# Selective frozen standard-module loading

## Status

Implemented for deterministic on-disk loading, persistent content-addressed standard frozen-interface caching, and a generated bootstrap fallback. Optional standard APIs are never collected inside user modules. The package driver resolves one canonical `dew.std` package root, reads only compiler-registered paths selected by leading imports, and supplies those bytes to independently collected reserved `dew.std.*` module identities. Generated byte tables remain available only through explicit bootstrap mode and produce byte-identical Wasm.

## Selection pass

Before semantic collection, `selected_standard_modules` consumes the same lazy parser event stream used by the frontend and scans only each file's contiguous leading import preamble. Its result selects compiler-owned modules rather than user-module source injection. It records:

- split text bits for `dew.std.string`, `dew.std.string_builder`, `dew.std.bytes`, and `dew.std.bytes_builder`;
- one WASI bit for `dew.std.wasi`;
- twenty lane bits in stable generated-source order.

`dew.std.preamble`, `dew.std.option`, and `dew.std.result` are ambient standard interfaces unless `--no-default-preamble` is selected. The pass stops at the first ordinary declaration and never regex-scans arbitrary source bytes.

A terminal wildcard is supported:

```dew
open dew.std.*
```

It selects every public standard module, including all twenty lane modules, but does not directly expose the private `dew.std.text_runtime` interface. Wildcard dependency expansion consumes only canonical module paths already present in `CollectedProgram`; it performs no filesystem discovery.

## Independent module boundaries

The collector appends selected standard modules after manifest modules with IDs in the reserved `0xffff0000..0xffff00ff` range. Important identities include:

```text
dew.std.preamble      0xffff0000
dew.std.text_runtime  0xffff0001
dew.std.option        0xffff0002
dew.std.string        0xffff0003
dew.std.string_builder 0xffff0004
dew.std.bytes_builder 0xffff0005
dew.std.bytes         0xffff0006
dew.std.wasi          0xffff0007
dew.std.result        0xffff0008
```

Lane modules retain reserved slots beginning at `0xffff0010`. Manifest order remains unchanged for user modules, while compiler-owned modules have deterministic dependency order independent of filesystem enumeration or package-root order.

## Package-root and source-provider model

The bootstrap launcher accepts repeatable ordered package roots:

```text
tools/dew check --package-root /opt/dew/packages main.dew
DEW_PACKAGE_ROOTS=/opt/dew/packages:/workspace/packages tools/dew build ...
```

Each root is checked without enumeration for either the installed layout:

```text
<root>/dew.std/std/...
```

or the checkout-compatible layout:

```text
<root>/std/...
```

Explicit command-line roots take precedence over environment roots; when either is supplied, a missing `dew.std` package is a usage error rather than silently falling back. With neither, the bootstrap launcher uses the compiler checkout root. Canonical physical roots never become semantic IDs: `dew.std` module IDs remain compiler-reserved constants.

`required_standard_library_source_paths` parses only manifest files' leading import preambles and returns a deterministic subset of the fixed source registry. A scalar program with defaults reads the eleven preamble files plus `option.dew` and `result.dew`; `open dew.std.*` reads all forty-two registered files, including `dew.std.fixed_array`, `dew.std.map`, and `dew.std.wasm.intrinsics`. The loader never scans a directory, follows a glob, or depends on filesystem order.

`StandardLibrarySources` maps exact logical paths to caller-provided bytes. `collect_program_manifest_with_standard_sources` consumes those bytes and falls back per missing path to the generated bootstrap provider. Production drivers fail while reading any required on-disk path, so fallback occurs only in explicit `--bootstrap-std` mode or compiler APIs that intentionally use `StandardLibrarySources::bootstrap()`.

The loader hashes the exact ordered selected path/source stream and stores diagnostics-free standard `FrozenModuleInterface` bundles under `.dew-cache/interfaces/`. Hits are decoded and identity-checked before the ordinary mixed cached/fresh SCC analysis. Cache artifacts have versioned semantic and envelope formats plus a SHA-256 payload checksum; corruption fails visibly rather than becoming a silent miss. See `docs/research/persistent-standard-interface-cache.md`.

`String`, `StringBuilder`, `Bytes`, and `BytesBuilder` import the private `dew.std.text_runtime` interface. String and Bytes search use ambient `Option<U32>`. Immutable range-copy implementations call private raw intrinsics and do not import public builder modules. Primitive/static impl evidence such as `StringBuilder::new()` survives interface freezing and imported dispatch.

## Generic standard sums

`dew.std.option` and `dew.std.result` define:

```dew
pub enum Option<t> {
  None
  Some(t)
}

pub enum Result<t, e> {
  Ok(t)
  Err(e)
}
```

Generic enum payload positions use deterministic erased physical fields for the six Wasm carriers (`i32`, `i64`, `f32`, `f64`, `v128`, nullable `eqref`). Constructors initialize the inferred carrier and deterministic zero/null defaults for the others; pattern lowering reads only the inferred carrier. This supports scalar, packed, SIMD, and reference payloads without per-instantiation type-index ordering. Generic functions and generic structs remain separate later ABI work.

## Reachability and artifact elimination

Whole-program planning now freezes cross-module roots before final indices:

- direct user and standard calls retain their actual owner declaration;
- compiler-private runtime edges cross module boundaries, including Bytes UTF-8 validation, dynamic test assertions, bounded WASI writes, and WASI imports;
- elided signatures receive no Wasm type slot and contribute no external type reference;
- unused standard nominal layouts, including unused ambient generic sums, are omitted;
- reachable imported aggregate layouts are retained through signatures, constructors, and patterns;
- final type/function indices remain deterministic in dependency-SCC order.

The previous `FindResult` nominal type and `dew.std.find_result` module were removed. Search APIs now return `Option<U32>`, while raw `0xffffffff` sentinels remain private runtime details.

## Remaining work

1. Add phase-only cache encode/decode/interface-resolution benchmarks and stable package ABI version release policy.
2. Extend package roots and cache keys beyond compiler-owned `dew.std` to versioned external package identities, integrity metadata, and dependency-interface fingerprints without introducing filesystem enumeration.
3. Remove generated bootstrap byte providers only after installed-source release layouts and cache recovery are independently reliable; retain an explicit no-default bootstrap mode for compiler tests.
4. Extend the generic ABI from aggregate enums to generic functions, methods, and structs, then specialize hot generic sums by physical shape if measurements justify it.
