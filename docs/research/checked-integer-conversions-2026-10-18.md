# Checked integer conversions

Four ordinary functions in `dew.std.math` check range before conversion:
`u32_checked_into_i32`, `i32_checked_into_u32`, `u64_checked_into_u32`, and
`i64_checked_into_i32`. They return `Option`; a range error does not trap.
Existing `Into` operations still provide their current bit/wrapping behavior.
No compiler intrinsic or conversion trait was added.

The module is generated by `tools/generate_math_std.py`. Direct imported tests
cover exact limits, one past each limit, zero, negative-to-unsigned, and source
integer extrema. They failed with missing-function diagnostics before the change
(0.258 s). With the library functions, the module built in 0.287 s and both tests
passed under Node. The source is `std/tests/checked_conversion_test.dew`; it is
also discovered by the full standard-library lane.

Each function does fixed work and returns the ordinary Option representation.
No new scratch buffer or retained data was added. No runtime or memory gain is
claimed. Existing compiler boundary checks are left in place; replacing them
with this API would need an allocation and runtime comparison first.
