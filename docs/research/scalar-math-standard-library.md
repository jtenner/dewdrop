# Scalar math standard library

## Scope

`dew.std.math` is the explicit scalar policy layer above Dew's ambient numeric
operators. It covers every fixed-width integer type plus `F32` and `F64` without
adding ambient traits, hidden allocation, or host-library dependencies.

The source is generated by `tools/generate_math_std.py` because eight integer
families share the same policy matrix. The generator owns both `std/math.dew`
and the bootstrap mirror in
`src/standard_sources/standard_math_sources.mbt`; generated-source validation
checks both byte-for-byte.

## Integer policy

Ordinary Dew integer operators already use fixed-width wrapping addition,
subtraction, multiplication, and negation. The math module makes that behavior
explicit through `*_wrapping_add`, `*_wrapping_sub`, `*_wrapping_mul`, and
signed `*_wrapping_abs` names.

Potentially failing arithmetic is non-trapping and returns `Option`:

- `*_checked_add`, `*_checked_sub`, and `*_checked_mul` return `None` on
  overflow;
- `*_checked_div` returns `None` for zero divisors and for signed
  minimum divided by `-1`;
- `*_checked_rem` returns `None` only for zero divisors and defines signed
  minimum remainder `-1` as exact zero, avoiding the underlying Wasm division
  overflow trap;
- signed `*_abs` traps only for the unrepresentable minimum value, while
  `*_wrapping_abs` returns that minimum unchanged.

Integer `min`, `max`, and `clamp` use the type's ordinary ordering. Clamp traps
when `lower > upper`; it never swaps or silently repairs an invalid interval.

The checked implementation stays allocation-free on successful and failing
arithmetic paths except for the language's existing `Option` representation.
It uses fixed-width overflow identities and guarded reverse-division checks, so
no wider integer carrier or host helper is required.

## Floating-point policy

Scalar float primitives map directly to deterministic WebAssembly Core
instructions:

- exact bit reinterpretation with `f32_to_bits`/`f32_from_bits` and
  `f64_to_bits`/`f64_from_bits`;
- `abs`, `sqrt`, `ceil`, `floor`, `trunc`, and ties-to-even `nearest`;
- exact-bit classification and `copysign` implemented in Dew source.

`f32_min`/`f64_min` and `f32_max`/`f64_max` do not delegate their policy to
Wasm `min`/`max`. They inspect operands in source order, return the first NaN
operand encountered without canonicalizing its payload, and define equal-zero
selection explicitly:

- minimum selects negative zero if either equal operand is negative zero;
- maximum selects positive zero if either equal operand is positive zero.

`f32_clamp` and `f64_clamp` preserve a NaN input unchanged, but NaN bounds or an
inverted interval trap. An in-range signed zero is returned unchanged rather
than being normalized.

These rules make NaN and signed-zero behavior testable through the public bit
reinterpretation API and independent of host language formatting or math
libraries. Arithmetic NaN payload production remains the underlying Core
instruction's behavior; the module only promises exact preservation where it
selects or bit-transforms an existing operand.

## Validation

Coverage includes:

- direct standard tests for checked, wrapping, boundary, classification,
  rounding, NaN, signed-zero, and expected-trap behavior;
- backend unit coverage for the new scalar instruction mappings;
- Node and Wago runtime snapshots for the public module and invalid clamp trap;
- deterministic generated-source, standard wildcard, selective-loading, and
  bootstrap-source checks.
